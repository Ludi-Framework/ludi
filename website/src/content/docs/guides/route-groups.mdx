`app:group(prefix)` gathers routes under a shared path prefix — like an
Express Router mounted on a path, or a Fastify plugin registered with a
`prefix`. Routes registered through the group get the prefix prepended
automatically.

The usual shape is a body callback that receives the group:

```lua
app:group("/api", function(api)
    api:get("/users", function(req, res)      -- GET /api/users
        res:json({ users = {} })
    end)

    api:post("/users", function(req, res)     -- POST /api/users
        res:status(201):json({ ok = true })
    end)
end)
```

The group is also returned, so the callback is optional:

```lua
local api = app:group("/api")

api:get("/ping", function(req, res)            -- GET /api/ping
    res:send("pong")
end)
```

All verb methods (`get`, `post`, `put`, `delete`, `patch`, `options`,
`head`) and path params work exactly as on the app; a `"/"` path maps to
the prefix itself:

```lua
app:group("/api", function(api)
    api:get("/", handler)                      -- GET /api
    api:get("/users/:id", handler)             -- GET /api/users/42
end)
```

## Group middlewares

A list of middlewares passed between the prefix and the body runs before
every route in the group:

```lua
local function auth(req, res, next)
    if req.headers["authorization"] then
        next()
    else
        res:status(401):json({ error = "Unauthorized" })
    end
end

app:group("/admin", { auth }, function(admin)
    admin:get("/stats", function(req, res)     -- auth runs first
        res:send("secret")
    end)
end)
```

`group:use` does the same, one middleware at a time — it applies to the
routes registered after the call:

```lua
local admin = app:group("/admin")
admin:use(auth)
admin:get("/stats", handler)
```

<Aside type="note">
	A lone function after the prefix is always the body callback. To pass a
	single middleware without a body, wrap it in a table —
	`app:group("/admin", { auth })` — or use `group:use`.
</Aside>

## Nesting

Groups nest; prefixes and middlewares accumulate:

```lua
app:group("/api", function(api)
    api:group("/v1", function(v1)
        v1:get("/users", handler)              -- GET /api/v1/users
    end)
end)
```

## Execution order

<Aside type="tip">
	Global middlewares → group middlewares (outermost first) → route
	middlewares → handler.
</Aside>

A group middleware that responds without calling `next()` short-circuits
the chain for every route in the group — that is how the `auth` example
above protects `/admin` as a whole.
