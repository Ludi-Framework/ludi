A middleware is a function `(req, res, next)`. The chain only advances when
`next()` is called — not calling it halts the request, express-style.

## Global middlewares

Registered with `app:use`, they run for every request:

```lua
app:use(function(req, res, next)
    print(req.method .. " " .. req.path)
    next()
end)
```

## Per-route middlewares

Pass a single function — or a list — before the handler:

```lua
local function auth(req, res, next)
    if req.headers["authorization"] then
        next()
    else
        res:status(401):json({ error = "Unauthorized" })
    end
end

app:get("/private", auth, function(req, res)
    res:send("secret")
end)

app:get("/very-private", { auth, audit }, function(req, res)
    res:send("very secret")
end)
```

## Group middlewares

A [route group](/guides/routing/#route-groups) takes a middleware list
between the prefix and the callback; it runs before every route in the
group. `group:use` adds one for the routes registered after the call:

```lua
app:group("/admin", { auth }, function(admin)
    admin:get("/stats", handler)    -- auth runs first
end)

local reports = app:group("/reports")
reports:use(auth)
reports:get("/daily", handler)
```

<Aside type="note">
	A lone function after the prefix is always the group's body callback. To
	pass a single middleware without a body, wrap it in a table — `{ auth }`
	— or use `group:use`.
</Aside>

## Execution order

<Aside type="tip">
	Global middlewares → group middlewares (outermost first) → route
	middlewares → handler, always in registration order.
</Aside>

A middleware that responds without calling `next()` short-circuits the chain
— the handler never runs. That is how the `auth` example above rejects
unauthenticated requests.
