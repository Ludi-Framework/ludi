Un middleware es una función `(req, res, next)`. La cadena solo avanza cuando
se llama a `next()` — no llamarlo detiene la petición, al estilo Express.

## Middlewares globales

Registrados con `app:use`, se ejecutan en cada petición:

```lua
app:use(function(req, res, next)
    print(req.method .. " " .. req.path)
    next()
end)
```

## Middlewares por ruta

Pasa una única función — o una lista — antes del handler:

```lua
local function auth(req, res, next)
    if req.headers["authorization"] then
        next()
    else
        res:status(401):json({ error = "Unauthorized" })
    end
end

app:get("/private", auth, function(req, res)
    res:send("secret")
end)

app:get("/very-private", { auth, audit }, function(req, res)
    res:send("very secret")
end)
```

## Middlewares de grupo

Un [grupo de rutas](/es/guides/routing/#grupos-de-rutas) acepta una lista
de middlewares entre el prefijo y el callback; se ejecuta antes de cada
ruta del grupo. `group:use` añade uno para las rutas registradas después
de la llamada:

```lua
app:group("/admin", { auth }, function(admin)
    admin:get("/stats", handler)    -- auth se ejecuta primero
end)

local reports = app:group("/reports")
reports:use(auth)
reports:get("/daily", handler)
```

<Aside type="note">
	Una función sola después del prefijo es siempre el callback del grupo.
	Para pasar un único middleware sin callback, envuélvelo en una tabla —
	`{ auth }` — o usa `group:use`.
</Aside>

## Orden de ejecución

<Aside type="tip">
	Middlewares globales → middlewares del grupo (el más externo primero) →
	middlewares de la ruta → handler, siempre en orden de registro.
</Aside>

Un middleware que responde sin llamar a `next()` corta la cadena — el handler
nunca se ejecuta. Así es como el ejemplo `auth` de arriba rechaza las
peticiones no autenticadas.
