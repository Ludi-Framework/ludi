Todos los métodos HTTP estándar están disponibles como métodos de la app:
`get`, `post`, `put`, `delete`, `patch`, `options`, `head`.

```lua
app:get("/hello", function(req, res)
    res:send("hi")
end)

app:post("/items", function(req, res)
    res:status(201):json({ ok = true })
end)
```

Los handlers reciben un [Request](/es/guides/request/) y un
[Response](/es/guides/response/).

## Parámetros de path

Los segmentos de path con prefijo `:` se capturan como params y se exponen en
`req.params`:

```lua
app:get("/users/:id/posts/:post_id", function(req, res)
    res:json({ user = req.params.id, post = req.params.post_id })
end)
```

Los params siempre son strings — `/users/42` produce `req.params.id == "42"`.

## Grupos de rutas

`app:group(prefix)` reúne rutas bajo un prefijo compartido — como un
Router de Express montado en una ruta, o un plugin de Fastify registrado
con `prefix`. La forma habitual es un callback que recibe el grupo; los
grupos se anidan, y la ruta `"/"` corresponde al propio prefijo:

```lua
app:group("/api", function(api)
    api:get("/", handler)                      -- GET /api
    api:get("/users/:id", handler)             -- GET /api/users/42

    api:group("/v2", function(v2)              -- los grupos se anidan
        v2:get("/users", handler)              -- GET /api/v2/users
    end)
end)
```

El grupo también se devuelve, así que el callback es opcional:

```lua
local api = app:group("/api")

api:get("/ping", function(req, res)            -- GET /api/ping
    res:send("pong")
end)
```

### Middlewares de grupo

Una lista de [middlewares](/es/guides/middleware/) entre el prefijo y el
callback se ejecuta antes de cada ruta del grupo; `group:use` añade uno
para las rutas registradas después de la llamada:

```lua
app:group("/admin", { auth }, function(admin)
    admin:get("/stats", handler)               -- auth se ejecuta primero
end)

local reports = app:group("/reports")
reports:use(auth)
reports:get("/daily", handler)
```

Orden de ejecución: middlewares globales → middlewares del grupo (del más
externo al más interno) → middlewares de la ruta → handler.

<Aside type="note">
	Una función sola después del prefijo es siempre el callback. Para pasar
	un único middleware sin callback, envuélvelo en una tabla —
	`app:group("/admin", { auth })` — o usa `group:use`.
</Aside>

## Rutas sin coincidencia

Las peticiones que no coinciden con ninguna ruta reciben un `404` con cuerpo
JSON.

## Errores en handlers

Los errores lanzados dentro de un handler se capturan y se responden con un
`500`.

<Aside type="note">
	El error se registra en stderr y **nunca se filtra al cliente**.
</Aside>
