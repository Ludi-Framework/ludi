Todos os métodos HTTP padrão estão disponíveis como métodos do app: `get`,
`post`, `put`, `delete`, `patch`, `options`, `head`.

```lua
app:get("/hello", function(req, res)
    res:send("hi")
end)

app:post("/items", function(req, res)
    res:status(201):json({ ok = true })
end)
```

Handlers recebem um [Request](/pt-br/guides/request/) e um
[Response](/pt-br/guides/response/).

## Parâmetros de path

Segmentos de path prefixados com `:` são capturados como params e expostos em
`req.params`:

```lua
app:get("/users/:id/posts/:post_id", function(req, res)
    res:json({ user = req.params.id, post = req.params.post_id })
end)
```

Params são sempre strings — `/users/42` resulta em `req.params.id == "42"`.

## Grupos de rotas

`app:group(prefix)` reúne rotas sob um prefixo compartilhado — como um
Router do Express montado em um caminho, ou um plugin do Fastify registrado
com `prefix`. A forma usual é um callback que recebe o grupo; grupos
aninham, e o caminho `"/"` mapeia para o próprio prefixo:

```lua
app:group("/api", function(api)
    api:get("/", handler)                      -- GET /api
    api:get("/users/:id", handler)             -- GET /api/users/42

    api:group("/v2", function(v2)              -- grupos aninham
        v2:get("/users", handler)              -- GET /api/v2/users
    end)
end)
```

O grupo também é retornado, então o callback é opcional:

```lua
local api = app:group("/api")

api:get("/ping", function(req, res)            -- GET /api/ping
    res:send("pong")
end)
```

Grupos também aceitam middlewares, que rodam antes de toda rota do grupo —
veja [middlewares de grupo](/pt-br/guides/middleware/#middlewares-de-grupo).

## Rotas não encontradas

Requisições que não casam com nenhuma rota recebem um `404` com corpo JSON.

## Erros em handlers

Erros lançados dentro de um handler são capturados e respondidos com `500`.

<Aside type="note">
	O erro é registrado no stderr e **nunca vaza para o cliente**.
</Aside>
