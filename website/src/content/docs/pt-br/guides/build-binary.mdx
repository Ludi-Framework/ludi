Como em Go, uma aplicação Ludi pode ser distribuída como um único
executável autocontido — sem Lua, sem LuaRocks na máquina de destino:

```bash
ludi build                    # entry auto-detectado quando nao ha ambiguidade
ludi build server.lua -o api  # ou entry e nome de saída explícitos
./api
```

O build é instantâneo: nenhum compilador roda. O `ludi build` empacota
todos os arquivos `*.lua` sob o diretório atual numa cópia do runtime do
`ludi` — um Lua 5.5 estático, o framework e o seu código num arquivo só.
Diretórios ocultos, `target/` e `lua_modules/` ficam de fora, as mesmas
regras do watcher do hot-reload.

Em execução, o `require` resolve de dentro do bundle; o filesystem nunca
é consultado para módulos. Deploy é `scp` e rodar.

## Detecção do entrypoint

Sem entry explícito, o `ludi build` aceita os nomes convencionais
`app.lua`, `server.lua`, `main.lua` e `init.lua` — mas só quando existe
exatamente um deles no projeto. Com dois ou mais presentes não há
palpite seguro (um `app.lua` ao lado de um `server.lua` costuma ser
módulo, não o runner), então o build para e pergunta:

```
ludi build: several possible entrypoints here (app.lua, server.lua); pass one: ludi build <entry.lua>
```

Qualquer nome de arquivo funciona quando passado explícito:
`ludi build qualquer.lua`.

## Obtendo o CLI

Cada release no GitHub traz o CLI por plataforma — baixe, `chmod +x`,
pronto:

```bash
curl -LO https://github.com/Ludi-Framework/ludi/releases/latest/download/ludi-linux-x86_64
chmod +x ludi-linux-x86_64 && sudo mv ludi-linux-x86_64 /usr/local/bin/ludi
```

macOS (Apple Silicon): use `ludi-darwin-arm64`. Ou compile do fonte com
`make cli` no repositório (requer Rust).

## Semântica

- Um binário bundlado sempre roda **Lua 5.5**, independente do
  interpretador usado no desenvolvimento.
- Argumentos de linha de comando chegam à aplicação como sempre
  (`arg[1]`, `arg[2]`, …).
- `LUDI_WATCH` é ignorada dentro do bundle — não há nada no disco para
  observar. Hot reload é para desenvolvimento; o binário é para deploy.

<Aside type="note">
	Só arquivos `*.lua` sob o diretório do projeto entram no pacote. O
	resto — rocks nativas como `fredy_core`, rocks Lua puras instaladas
	via LuaRocks — resolve do sistema em execução, então precisa estar
	instalado (compilado para Lua 5.5) na máquina destino. Uma aplicação
	Lua pura sem rocks externas roda em qualquer lugar.
</Aside>
